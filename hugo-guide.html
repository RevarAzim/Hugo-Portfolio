Hugo, and how this site works

Hugo is a program that reads your text files and fills in HTML templates. The result is a folder of ordinary web pages. Nothing on the site is a database or a running app.

You do not need to learn all of Hugo. For this project you mostly edit a few text files, then push them to GitHub. GitHub builds the site and publishes it.

The one idea

A normal website is HTML you write by hand. Hugo splits that into two parts:

  1. Your facts. Your name, jobs, schools, and project write-ups. These are plain text.
  2. The shape of the page. Where the name goes, how the menu looks, how a project card is drawn. These are templates.

When you run Hugo, it loops over the facts and stamps them into the templates. The finished HTML lands in a folder called public/. You never edit public/. The next build overwrites it.

This site has no theme from the internet. Every template is in layouts/, and the CSS is in assets/css/. If the page looks a certain way, the reason is a file in this project.

Things you will actually do

Change your name, summary, email, phone, or links

Open data/profile.yaml. Change the text after the colon. Keep the quotes around the phone number. phone is what people read. phone_href is the tap-to-call link, and it must start with tel:.

email: revar.azim@gmail.com
phone: "0770 966 4486"
phone_href: "tel:+9647709664486"
linkedin: https://linkedin.com/in/revar-azim
github: https://github.com/RevarAzim

The home page, the contact page, and the footer all read this one file. Change it once and all three update.

Change a job

Open data/experience.yaml. Each job starts with a dash. The bullets under points: are the sentences on the page. start_label and end_label are the dates people see. start and end are the machine-readable versions, like 2025-11.

project: anyprompts adds a link to content/projects/anyprompts.md. The value is the filename without .md.

Change education, skills, or spoken languages

  • data/education.yaml for the degree.
  • data/skills.yaml for the groups on the skills page. Add a line under items:, with a dash and a space.
  • data/languages.yaml for Kurdish, English, and Arabic.

These lists are the CV. A technology you used on one project belongs on that project, not automatically in the skills list.

Edit a project you already have

Projects are Markdown files in content/projects/. The top of the file, between the --- lines, is called front matter. Hugo reads it as data. Everything under the second --- is the article.

---
title: Signalize
description: One sentence for the project list and for Google.
dek: A short line under the title
status: Under development
weight: 1
technologies:
  - Flutter
  - Dart
---

The long description starts here. This part is Markdown.
  • title is the project name.
  • description is the short text on the project list, and the sentence search engines use.
  • dek is the line under the title on the project page.
  • status is a label such as “Under development”.
  • weight sets the order. Smaller numbers come first. Signalize is 1, then AnyPrompts 2, Sat 3, UniLink 4.
  • technologies is a list of names. The page prints them as one line of text. They are not links, and there is no page for each technology.

In the article, a line that starts with ## is a heading. A line that starts with - is a bullet. [TechnoBase internship](/experience/) is a link. The text in brackets is what people see. The path in parentheses is where it goes. Write site links as /experience/, with a leading slash. A small template rewrites that so it still works inside /Hugo-Portfolio/.

Add a new project

Copy content/projects/signalize.md to a new file, for example content/projects/my-app.md. The filename becomes the address: /projects/my-app/. Use lowercase and hyphens. Then replace the title, description, technologies, and article with the real project. Give it the next weight.

You can also run this from the project folder:

hugo new content/projects/my-app.md

That creates a file with draft: true. A draft is hidden from the live site. Delete the line draft: true when you want it published. Until you do, you can still see it locally with the draft preview command in the Commands section below.

Change the menu

The menu is not in the HTML. It is the list at the bottom of hugo.toml. Each item has a name (the word in the menu), a url, and a weight (left-to-right order). The current page is bold with a thicker underline. That comes from layouts/partials/nav.html, which compares the menu item with the page you are on.

Change colours or type

Open assets/css/main.css. The colours are the four variables at the top: paper background, ink, muted text, and the hairline. Print rules are a separate file, assets/css/print.css. Hugo compresses both and gives them a fingerprint in the filename so browsers do not keep an old copy.

Home is the page that prints as the CV. The print stylesheet hides the menu. On the home page it also hides the footer, because the contact details are already at the top.

How one page is built

Every HTML page starts from layouts/_default/baseof.html. That file is the skeleton: the skip link, the header, <main>, and the footer. The middle is a hole named main. Each page template fills that hole.

Pieces that repeat are partials, in layouts/partials/:

  • head.html is the title, description, canonical link, and Open Graph tags. It also attaches the CSS.
  • nav.html prints the menu from hugo.toml.
  • experience-list.html, education-list.html, skills-list.html, and languages-list.html loop over the YAML files.
  • contact-links.html prints email, phone, LinkedIn, and GitHub. On the contact page it adds icons and puts each one on its own line.
  • project-card.html is one project in a list.

A template line looks like this:

{{ hugo.Data.profile.name }}

The {{ }} means “print this value”. hugo.Data.profile is the contents of data/profile.yaml. .name is the name: field.

A loop looks like this:

{{ range hugo.Data.skills }}
  {{ .group }}
{{ end }}

range means “once for each item”. Inside the loop, . is the current item. {{ end }} closes the loop. You can ignore the rest of the template syntax until you want to change the layout itself.

Which template Hugo picks:

  • The home page is layouts/index.html, fed by content/_index.md.
  • A page can ask for a template by name. content/about.md says layout: about, so Hugo uses layouts/_default/about.html.
  • Anything in content/projects/ uses layouts/projects/list.html for the list and layouts/projects/single.html for one project.

Words Hugo uses

WordMeaning here
Front matterThe --- block at the top of a Markdown file. Title, description, technologies, draft.
DraftA page with draft: true. Left out of the live site until you delete that line.
Base URLThe public address, https://revarazim.github.io/Hugo-Portfolio/. The trailing slash matters. Internal links are built from it, which is why the site can live in a subfolder.
PartialA small template included by other templates. The menu is a partial.
MarkdownThe simple writing format in content/. ## is a heading, - is a bullet, [text](/path/) is a link.
YAMLThe format in data/. Indentation matters. Use spaces, not tabs. A list item starts with -.
MinifyRemove extra spaces from the finished HTML and CSS so the files are smaller.
FingerprintA hash in the CSS filename. When the CSS changes, the filename changes, so browsers download the new file.

Commands

Open Terminal, then:

cd "/Users/revar/Desktop/Hugo Portfolio"

Preview the site on your computer. Leave this running. Hugo rebuilds when you save a file.

hugo server --baseURL http://127.0.0.1:1313/

Open http://127.0.0.1:1313/. The extra --baseURL is only for your computer. The file hugo.toml still holds the GitHub address, and that address includes the folder /Hugo-Portfolio/. Without the local override, the preview asks for CSS inside that folder, the local server does not have it, and the page shows up unstyled.

To preview a page that is still a draft, add --buildDrafts:

hugo server --buildDrafts --baseURL http://127.0.0.1:1313/

Check the real build. Drafts are omitted, and any warning stops the command:

hugo --minify --panicOnWarning

That writes public/. You can ignore that folder.

Hugo on this machine is v0.170.1. There is no separate “extended” install to hunt for. This version already includes what used to be the extended edition.

How publishing works

The live site is https://revarazim.github.io/Hugo-Portfolio/. The source is the GitHub repository RevarAzim/Hugo-Portfolio.

You do not upload public/. You push the source. GitHub’s Action installs Hugo, runs the build, and publishes the result. The workflow file is .github/workflows/hugo.yml. It runs on every push to main.

git add .
git commit -m "Describe what you changed."
git push

Wait about a minute, then refresh the live page. If the old page is still there, refresh again. Browsers keep the previous CSS for a short time.

git add . will not add public/, because .gitignore excludes it. That is what you want.

The pages that are on the site now are not drafts. A new file you create with hugo new is a draft until you remove draft: true. If you push a draft, the live site will not include that page, and the build will still succeed.

Rules for this project

  • Only put facts you can point to: the CV, or something you have explicitly added, such as Signalize and the LinkedIn URL.
  • Do not invent employers, dates, numbers, skills, or links. If something is missing, write it in OPEN-QUESTIONS.md and decide later.
  • The phone number and LinkedIn profile are on the site because you asked for them. Do not add a home address, date of birth, or ID number.
  • The section about 19 AI coding agents was removed on purpose. Do not put it back unless you want it.
  • Signalize is not on the CV PDF. The text on the site is the description you supplied. Keep later edits inside that description.
  • No API keys or passwords anywhere in the project.
  • New pages start as drafts. Remove draft: true yourself when the page is ready.
